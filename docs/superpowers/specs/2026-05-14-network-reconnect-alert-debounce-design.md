# 客户端网络重连提示降噪设计

## 背景

客户端 WebSocket 已有自动重连机制。当前问题不是重连失败，而是网络短暂闪断时，UI 会过早显示“服务器已断开”等错误提示。很多短闪会在几秒内自动恢复，频繁提示会打扰用户。

## 目标

- 保持现有 WebSocket 自动重连机制不变。
- 只调整客户端提示展示策略。
- 短暂断线不提示，用户无感。
- 断线持续超过 5 秒后，再显示现有错误浮层。
- 恢复连接后，错误浮层自动消失。

## 非目标

- 不修改 `WsService` 的连接、退避、重试次数或重试节奏。
- 不修改 Server 或 Gateway 协议。
- 不增加新的网络探测机制。
- 不改变 401 认证失败处理。

## 方案

在 `MainLayout` 的连接提示层增加 UI 防抖：

1. 当 WebSocket 从已连接状态变为非连接状态时，不立即展示错误浮层。
2. 启动一个 5 秒延迟窗口。
3. 如果 5 秒内恢复连接，取消本次提示。
4. 如果 5 秒后仍未连接，才允许展示现有错误浮层。
5. 连接恢复后，重置本次断线计时和提示状态。

首次启动的 8 秒宽限期继续保留，和本次断线防抖互不替代。

## 用户体验

- 网络闪断 1-3 秒：不显示错误提示。
- 网络持续断开超过 5 秒：显示现有错误浮层，保留现有重试按钮。
- 自动重连恢复后：浮层消失。
- 认证失败：继续立即弹认证失败对话框，不等待 5 秒。

## 测试

新增或更新 Flutter widget 测试，覆盖：

- `disconnected` 未超过 5 秒时不展示错误浮层。
- 超过 5 秒仍断开时展示错误浮层。
- 5 秒内恢复连接时不展示错误浮层。
- 认证失败流程不受影响。

## 验收标准

- 短暂网络闪断不会出现“连接异常”提示。
- 长时间断线仍能提示用户，并保留现有手动刷新入口。
- 现有自动重连行为保持不变。
